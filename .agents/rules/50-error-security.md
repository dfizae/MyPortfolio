# 오류 처리, 개인정보, 보안

## 오류 처리

- 예외를 빈 `catch`로 삼키거나 `console.log`만 남기고 끝내지 않는다.
- 기술적인 오류 메시지를 화면에 그대로 보여 주지 않는다. 안내 문구는 `Text.ts`에 둔다.
- 폼 입력 오류는 그 필드 가까이에 보인다(Contact 폼의 Formspree `ValidationError`).
- 전송에 실패해도 입력값을 지우지 않고 다시 보낼 수 있게 한다. 보내는 중에는 버튼을 막아 중복 전송을 막는다.
- 없는 주소와 없는 글은 404로 끝낸다(규칙 20). 렌더링 오류를 영역별로 격리해야 하면 라우트 모듈의 `ErrorBoundary` export를 쓴다. 지금은 없으니 새로 들일 때는 확인을 요청한다.
- 보여 줄 데이터가 없으면 빈 틀을 남기지 않는다. 기존 방식을 따른다: 글이 없으면 홈 글 섹션을 그리지 않고(`src/pages/main/Posts/index.tsx`), 글이 적은 분류는 메뉴에서 숨긴다(`POST_CATEGORIES`의 `minPostsForNav`).

## 개인정보 (공개 사이트, 공개 저장소)

- 누구나 여는 페이지다. 생년월일과 거주지는 싣지 않고, 연락처 번호는 가린 채로 둔다(DESIGN.md §9 2026-10-12). 이 규칙을 완화하는 요청은 위험을 먼저 알린 뒤 진행한다.
- 저장소도 공개다. 커밋하는 파일에 비밀 키, 토큰, 개인 메모, 로컬 전용 문서의 내용을 쓰지 않는다.

## 보안과 환경 변수

- `import.meta.env`의 `VITE_` 값은 브라우저 번들에 그대로 들어간다고 본다. 비밀 값을 넣지 않는다. Formspree 폼 id는 공개되는 값이다.
- `dangerouslySetInnerHTML`은 빌드 때 이 저장소의 md로 만든 글 HTML(`src/pages/blog/PostArticle.tsx`)에만 쓴다. 외부(RSS, API)에서 받은 텍스트와 사용자 입력은 문자열로 렌더링한다.
- 주소와 검색 파라미터 값은 믿지 않고 검증한 뒤 쓴다.
